Audit date: 2026-11-22. Tools: `sitemap_discovery.py --expand --json`, a full fetch of every `<loc>` (2,348 GETs), and a parse of each page's canonical, robots and hreflang compared against the sitemap entry. Generator: `writeSitemap()` in `react-router.config.ts`, run at `buildEnd`, written to `dist/client/sitemap.xml`.

### Programmatic page quality gate

No location pages, so the location gates do not apply. The 521 set pages × 4 locales are data-driven pages from game data, the "product pages with unique specs" pattern: raw-HTML word count 398–1,947 (median 632), each with its own items, bonuses and stats, and every one is linked from the `/sets` index and from at least one other page (inlinks 2–107, median 7). Safe at this scale. Watch the thinnest set pages (~400 words) in Search Console for "Crawled – currently not indexed".

## Findings

### S1. Sitemap (and prerendered build/profile pages) only refresh at deploy time
- **Severity:** Medium
- **Evidence:** `react-router.config.ts` reads public builds from Supabase once in `fetchPublicBuilds()` during `pnpm build` and writes them into `sitemap.xml`. Builds published after a deploy are missing until the next deploy; builds deleted or made private after a deploy stay listed until then, and those URLs are served as the 200 home-canonical app shell (see technical finding H1), which Search Console reports as "Submitted URL… duplicate, Google chose different canonical" or "Soft 404". Newest build lastmod in the live file is 2026-11-21.
- **Recommendation:** serve the dynamic part from the Worker: split into a sitemap index (`/sitemap.xml` → `/sitemap-static.xml` prerendered + `/sitemap-builds.xml` generated by the Worker from Supabase on request, cached ~1 h at the edge). Alternatively schedule a daily rebuild/deploy. In both cases make removed builds return 404/410 (technical H1) so stale entries clean themselves up.
- **Source:** `react-router.config.ts` (`fetchPublicBuilds`, `dynamicPages`, `writeSitemap`), `src/worker/index.ts`.

### S2. A build without Supabase credentials silently ships a sitemap with no builds or profiles
- **Severity:** Low
- **Evidence:** `fetchPublicBuilds()` logs a warning and returns `[]` when `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` are missing or the request fails; the build still succeeds. A deploy from such a build would drop all 148 build/profile URLs from the sitemap and stop prerendering them.
- **Recommendation:** fail the production build (or the deploy step) when the list is empty but credentials were expected, or compare the URL count against the previous deploy and alert on a large drop.
- **Source:** `react-router.config.ts` lines ~56–83.

### S3. `<lastmod>` missing on 140 URLs and uniform on set pages
- **Severity:** Low
- **Evidence:** no `<lastmod>` on the 36 static pages, 4 `/sets` index URLs, 76 class guides and 24 profiles. All 2,084 set pages carry `2026-10-20`, which equals `public/data/version.json` `generatedAt` (game 3.7.12.12). That date is honest for the game data, but it does not move when the set page template or copy changes, so Google learns that lastmod does not track page changes.
- **Recommendation:** class guides: use the same game-data date (they are built from the same data); static pages: the git commit date of the page component/locale strings at build time; `/sets` index: game-data date; profiles: the newest `updated_at` of the author's public builds; set pages: `max(game-data date, date of the last set-page template change)`.
- **Source:** `react-router.config.ts` `writeSitemap()` (the `lastmod` Map only covers `sets/*` and `build/*`).

### S4. Single file mixes every content type
- **Severity:** Info
- **Evidence:** one 1.44 MB `urlset` with static, set, class, build and profile URLs.
- **Recommendation:** optional: a sitemap index with per-type children (`static`, `sets`, `classes`, `builds`, `profiles`). Search Console then reports indexing per type, which makes the set-page and build-page coverage easy to track. Required anyway if S1 is done via the Worker.
- **Source:** `react-router.config.ts` `writeSitemap()`.

### S5. Two set pages per locale share a title
- **Severity:** Info (detailed in technical L4)
- **Evidence:** `/sets/abyss-set` and `/sets/abyss-set-956` (two distinct in-game sets with the same name) both titled "Abyss Set (Lvl 200) — Bonuses, Items & Stats | Dofus 3"; `/es/sets/depths-set` and `/es/sets/chasm-set` both "Set de la sima (Nv. 200)…". Both URLs are legitimately distinct and correctly listed; only the titles need disambiguating.
- **Source:** `src/data/setGuide.ts`, `src/pages/SetPage.tsx`.
